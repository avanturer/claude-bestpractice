```sh
claude plugin marketplace add avanturer/claude-bestpractice
claude plugin install founder-os@founder-os
```

Либо так — чтобы гейты были проверены на вашей машине **до** того, как что-либо
зарегистрируется:

```sh
curl -fsSL https://raw.githubusercontent.com/avanturer/claude-bestpractice/HEAD/install.sh | bash
```

Это вся установка. Дальше в любом репозитории:

```sh
founder-os init      # вывести из вашего кода то, что выводится; спросить про остальное
founder-os status    # всё сразу
```

Инсталлятор запускает доктора **до** регистрации плагина и отказывается ставиться, если
хотя бы один гейт не срабатывает. Гейт, который молча ничего не делает, хуже, чем его
отсутствие.

## Проблема

Вы строите продукт почти полностью через Claude. Одновременно работают три–восемь
сессий в отдельных worktree. Диффы вы почти не читаете. Что именно ломается — измерено,
а не выдумано:

| | |
|---|---|
| Агент говорит «готово», а код не работает | **0.97** сдач против **0.65** подтверждённых тестами. Два разных охранных промпта сдвинули это на **ноль** |
| Правит корректный код, который его не просили трогать | **60–90 %** прогонов на четырёх frontier-моделях в ситуациях, где правильно было воздержаться |
| Правила размываются по мере роста сессии | 0 % нарушений → **30 %** после одной компактификации → **78 %** после четырёх |
| Слишком много правил обрушивают соблюдение | **93.8 %** идеально при 10 правилах → **75 %** при 20 → **23.8 %** при 40 → **0 %** при 80 |
| Устаревший контекст хуже, чем никакого | Только устаревший retrieval дал вызовы мёртвых API в **15/17** примерах; без retrieval — **0/17** |

Источники по каждой цифре — в [`EVIDENCE.md`](EVIDENCE.md).

## Дизайн одним предложением

**Ничто важное не просится у модели.** Каждое правило, которое обязано соблюдаться,
принуждается харнессом или git; в контекст модели попадает только то немногое, что не
проверяется программой.

## Что вы получаете

### Память, которая не может протухнуть

Три слоя, разделённые по признаку *что именно делает каждый из них ложным*.

| Слой | Содержимое | Почему остаётся истинным |
|---|---|---|
| **Derived** | Карта символов, результаты тестов, показатели здоровья | Пересобирается из кода и штампуется исходным коммитом. Устаревший артефакт — это падение сборки, а не уверенный неверный ответ |
| **Decided** | Продукт, non-goals, сущности, глоссарий, решения | Неизменяемый. Решение — исторический факт: отменяется более поздней записью, которая его называет, а не переписыванием истории |
| **Ephemeral** | Сессии, лизы, заявки, лимиты | На сессию, в gitignore, с TTL, подчищается ридером |

Каждое утверждение несёт **git blob-хеши** кода, который описывает — никаких mtime,
которые checkout worktree сбрасывает целиком. Когда предмет утверждения переписан,
утверждение подавляется и учитывается, а не удаляется молча.

Каждая сущность называет канонический идентификатор и его файл. Переименование
**валит валидацию**, вместо того чтобы оставить память описывающей то, чего больше нет.

### Сессии видят друг друга

```
OTHER LIVE SESSIONS (2) — do not edit files they hold:
  - a3f81c22 on feat/export  [ledger-export]  active 40s ago
      touched: src/billing.js, src/csv.js
      holds: src/billing.js
      task: Add CSV export to src/billing.js

IN FLIGHT:
  - 0004 Fix rounding in invoice totals  [b7d29e01]
NEXT:
  - 0005 Add client search
(12 done)

health: 3 live session(s), 1 reaped, 4 open item(s), 1 stale (suppressed)
```

Правка файла, который держит другая живая сессия, **запрещается** с указанием владельца.
Лизы и заявки упавшей сессии освобождаются ридером — в том worktree, где они лежат, — а
не висят в работе вечно.

Замолчавшая сессия **не** считается мёртвой. Реапинг по молчанию означал, что основатель,
подумавший пятнадцать минут, возвращался в сессию, где все гейты перестали что-либо
принуждать; теперь смерть требует, чтобы процесс исчез или его pid был переиспользован.

### Журнал работ, который мержится

`.claude/founder-os/plan/{next,doing,done}/` — один файл на задачу, состояние закодировано
в директории, поэтому переход — это `git mv`. Пять worktree дают пять чистых add вместо
пяти конфликтующих кусков в одном JSON. Идентификаторы выделяются с оглядкой на все
соседние worktree, потому что worktree делят пространство имён ещё до того, как их файлы
вообще закоммичены.

### Завершение принимается по доказательству

Stop-гейт **выбрасывает прозу агента** и сам запускает ваш набор тестов, считая
доказательством собственный наблюдённый код возврата. Файл, утверждающий, что тесты
прошли, — это утверждение с угловыми скобками: написанный руками, взятый из чужого
проекта и просто `touch junit.xml` — все три обошли раннюю версию этого гейта, которая
артефакт читала.

Начиная со стадии выше прототипа он дополнительно перезапускает тесты на чистом checkout
закоммиченного дерева — это ловит класс «зелено у меня, красно у всех»: незакоммиченный
файл, локальная переменная окружения.

Он также эскалирует, а не заклинивает: после четырёх заблокированных попыток он
записывает неподтверждённое завершение и отпускает ход, потому что гейт, который вечно
блокирует работу основателя, — это гейт, который сносят.

### Код, написанный для следующей модели

Докстринги обязаны нести невыводимую информацию. `Args:` / `Returns:` / `:param:`
запрещены прямо — типы уже это говорят. Изменение сигнатуры без изменения докстринга
**валит коммит**.

> Если вы собираетесь написать комментарий о том, чем является значение, напишите тип.

### Слоп ловится механически

Проглоченные исключения, абстракции с одним вызывающим, compat-прослойки без
потребителей, дублирующиеся блоки, неиспользуемые параметры — **вечный бюджет ноль**.
Сложность и длина идут по храповику: базовая линия ставится один раз, дальше только вниз.

### Строгость масштабируется сама

Стадия вычисляется по репозиторию, никогда не настраивается, и храповик только затягивает.

| Обнаруженный сигнал | Что включается |
|---|---|
| CI плюс цель деплоя | Правила egress, шлюз для продовых сигналов |
| Миграция, создающая таблицу users, или auth SDK | Гейт миграций, запрет промоушена в прод, своя БД и порт на worktree |


### Проверки выполняются локально, а не на чужом счётчике

`founder-os init` ставит **pre-push хук**, который прогоняет ваш собственный
`make check` — или доктора, если своих проверок нет — до того, как что-либо покинет
машину. Бесплатно и вовремя, чтобы остановить push, а не прислать письмо постфактум.

Это дефолт, потому что hosted-минуты платные, а этот режим работы тратит их как целая
команда: три–восемь сессий пушат весь день, счёт один.

Поставляемый workflow GitHub Actions **закрыт переменной репозитория** и не стоит ничего,
пока вы его не включите:

```sh
founder-os-ci status     # что где выполняется
founder-os-ci github     # включить hosted CI (ставит переменную через gh)
founder-os-ci off        # снять pre-push хук
```

Одно другому не мешает: pre-push хук обязывает только те машины, где он установлен,
поэтому репозиторию, куда пушат другие, hosted-прогон всё равно нужен. Разовый обход —
`git push --no-verify`: это осознанное действие, оставляющее след, в отличие от молча
пропущенного hosted-прогона.

### Он забирает под себя то, что ему мешает

`founder-os adopt` находит другие инструменты, оспаривающие события, которыми владеет
этот плагин, помещает их хук-записи в помеченный блок с бэкапом и говорит, какие именно
конкурирующие плагины отключить. Обратимо через `--restore`. Он никогда не удаляет чужую
конфигурацию молча.

## Гейты

| Гейт | Событие | Поведение при сбое | Что делает |
|---|---|---|---|
| `setup` | Setup | fails open | Выводит слой знания, создаёт план, засевает стадию |
| `session-start` | SessionStart | fails open | Подчищает мёртвых, регистрирует, вкидывает борд + план + стадию |
| `prompt-capture` | UserPromptSubmit | fails open | Записывает задачу дословно. **Ничего не вкидывает** |
| `pre-tool` | PreToolUse | **fails closed** | Потолок вызовов, разрыв цикла, скан секретов до записи, лизы, гейт миграций и деплоя |
| `review-commit` | `if: Bash(git commit:*)` | async rewake | Ревьюит дифф этого хода; будит только когда есть что сказать |
| `worktree-create` | WorktreeCreate | fails open | Именует, засевает доверие, выводит приватный порт и БД |
| `subagent-brief` | SubagentStart | fails open | Non-goals, сущности и карта под запрос — агентам, которые не наследуют правил |
| `checkpoint` | PreCompact | fails open | Экстрактивный чекпойнт, ноль вызовов модели, секреты вычищены |
| `evidence-gate` | Stop | **fails closed** | Дрейф скоупа, тестовое доказательство, чистый повторный прогон; собирает черновики решений |

Девять записей против самоограничения в двенадцать. Постоянный контекст **~329 токенов**
против потолка в 400 — примерно 0.1 % окна на 200k.

## Проверено

```
make check    # lint · docs gate · slop gate · polyglot gate · knowledge · 540 тестов · 25 проверок доктора · budget
```

Доктор доказывает гейты **попыткой сделать плохое**, а не чтением конфигурации обратно —
readback конфига не способен обнаружить изменение семантики. Семнадцать реальных багов,
найденных за разработку, были невидимы для чтения кода и пойманы только исполнением,
включая дедлок, где evidence-гейт требовал тестовый артефакт, а затем блокировал сессию
за то, что она его произвела.

Набор включает полный жизненный цикл проекта, прогоняемый целиком через настоящие
исполняемые гейты: онбординг незнакомого репозитория, планирование, утёкший креденшл,
нарушение скоупа, падающий набор тестов, зелёное завершение и вторую сессию, читающую
историю.

## Требования

Python 3.9+ и git. **Никаких других зависимостей, по конструкции** — эти хуки бегут на
каждом вызове инструмента, поэтому дерево зависимостей — это латентность, лишний режим
отказа и supply-chain поверхность для компонента, вся работа которого — быть достойным
доверия. Проверяется в CI.

Протестировано на Python 3.9, 3.11 и 3.13. `claude plugin validate --strict` проходит
на Claude Code 2.1.220.

### Что появится в вашем репозитории и что с этим делать

Две директории, и разница между ними существенна:

**`.claude/founder-os/` — это коммитить.** Задачи, решения, тупики, маркер стадии.
Лежит внутри репозитория сознательно, потому что должно ехать вместе с веткой: решение,
принятое на `feat/billing`, — это решение про `feat/billing`, а список задач, который не
переживает переключение ветки, хуже, чем его отсутствие. Один файл на элемент, поэтому
пять воркtree дают пять чистых add вместо пяти конфликтующих кусков в одном блобе.
Ничего меняющегося от запуска к запуску там нет, так что оно не всплывает диффом каждый
раз, когда срабатывает гейт.

**`.git/founder-os/` — игнорировать, git уже игнорирует.** Живые сессии, лизы, счётчик
петель, чек теста. Лежит в общей git-директории, потому что это единственный путь,
который разделяют все воркtree одного клона, невидим для git, переживает переключение
веток и умирает вместе с клоном. Полностью восстановим: `founder-os reindex` пересобирает
его из закоммиченной половины, и этот путь протестирован, а не предположен.

Руками не редактируется ни то, ни другое. Если хотите убрать всё — удалите обе
директории и снесите плагин; больше на машине ничего не тронуто.

### Стоимость контекста

Панель `/plugin` в Claude Code показывает, сколько плагин добавляет в контекстное окно
на каждом ходу, — то есть это число, которое можно сравнить, а не обещание, в которое
надо поверить.

founder-os держит **~332 токена** постоянного контекста в четырёх компонентах при
самоназначенном потолке в 400. `make check` роняет сборку при превышении, и потолок
держали урезанием описаний, а не поднятием планки — дважды.

Всё остальное грузится по требованию: скиллы — только когда срабатывает их триггер,
доска — только на старте сессии, журнал работ — только когда его спросили. Бюджет
существует потому, что стоимость видна в вашей же панели расхода, а польза
контрфактуальна и невидима, — и это размен, который основатель имеет право проверить.

## Чем это сознательно не является

- **Не движок памяти.** Харнесс хранит и загружает память. Этот плагин владеет курацией.
- **Не код-ревьюер.** Есть несколько first-party путей ревью; выберите один и интегрируйте.
- **Не таск-менеджер.** Нативная система задач поглощается и гейтится, но не заменяется.
- **Не для команд.** Каждый компромисс предполагает одного владельца и отсутствие ревьюера.

## Четыре вещи, которые он не может принудить

Сказано прямо, потому что нормой в этой категории является ложная уверенность.

1. **Семантика тестов.** Ни один матчер не отличает оправданный skip от жульничества.
2. **Вкус.** Ни один матчер не отличает хороший дизайн от плохого.
3. **`claude --bare`.** Он сбрасывает и managed-, и плагинные хуки. Именно поэтому
   существует слой репозитория — настоящие git-хуки, CI, защита веток.
4. **Человек с root.** По замыслу.
